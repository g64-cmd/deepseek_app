# Android 阶段 C 推进方案

日期：2026-11-22（Asia/Singapore）。研究基线：`develop` / `981428e` / chat-demo `0.1.3`。

阶段 C 建议按 **校准性能测量 → 富内容按需渲染与可访问性修复 → 历史检索与规模验收** 推进，并补齐阶段 B 遗留的附件上下文与费用保护。完整备份和基础用量统计已经实现，改列规模验收；列表虚拟化、SQLite 和原生传输扩展由新测量结果决定。OCR、独立 Search/Fetch、WebSocket 朗读继续作为可选项。

本方案于 2026-11-22 完成研究，随后完成 C0 工具与离线模拟器基线：固定夹具、独立测试包、稳定测量标识、ADB/CDP 驱动、切换矩阵、trace、20 轮内存及大备份闭环，见[C0 测量记录](android-phase-c0-baseline.md)。**C1 富内容按需渲染已于 2026-11-23 实施并通过模拟器前后对照**（混合热切换中位 40.1→1.69 秒，混合与冻结目标达到；纯文本冷切换复核见验证记录第 11 节），见[阶段 C 验证记录](android-phase-c-verification.md)。**C4 附件上下文与费用保护于同日补齐代码与自动回归**，详见验证记录第 9 节；真实收费上传与设备操作仍待验。**C2 可访问性与移动适配的首批代码已于 2026-11-24 实施**，首批模拟器证据见验证记录第 12 节，C2 review 五项修复和带真实样式的 17 项回归见第 13 节；TalkBack 和目标真机仍待验。**C3a/C3b 历史检索已于 2026-11-24 实施**：标题过滤、可取消正文扫描和任意分支定位，首批证据见第 14 节，review 修复见第 15 节，读库阶段取消补修及 22 项正式浏览器回归见第 16 节。Gemini 复审后的增量修复见第 17 节，当前 **128/128** 回归、类型、lint、生产 Web 与常规 debug 构建通过。设备性能、TalkBack 和真实 API 的既有证据范围见[阶段 A](android-phase-a-verification.md)与[阶段 B](android-phase-b-verification.md)记录。

## 2 C0 校准测量与重新建立基线

### 历史结果的适用范围

[阶段 B 性能报告](android-phase-b-perf.md)记录了旧 APK（运行时代码基线 `8e93e62`）在 Pixel_8 AVD / API 34 / WebView 113 上的混合会话首切 16.7 秒、二切 8.2 秒，以及两次 49～67 秒冻结。这足以把渲染列为优先研究方向，但不是当前 `981428e` 的复测结果；冻结的具体来源仍需 trace 分析。

保留的 [perf-seed.js](../scripts/perf-seed.js) 与历史报告有以下口径差异，必须在新测量前校准：

| 当前夹具 | 源码实际生成 | 历史报告描述 |
| --- | --- | --- |
| 长代码块 | 200 个四行函数，约 800 行 TS | 200 行 |
| 300 条混合消息 | 150 问答轮次，30 个代码块、240 个 display 公式、30 张 Mermaid | 分析段写 60 个代码块、384 个公式 |
| 50 条重图表消息 | 25 条用户消息，13 条 Mermaid 回答、12 条公式密集回答（96 个公式） | 25 Mermaid + 25 公式 |

这些差异不用于反推或改写历史耗时。新记录应保存提交、构建模式、夹具 SHA-256、实际消息/富内容数量、附件字节与像素尺寸、设备和 WebView 版本。研究时旧 `perf-seed.js` 的 SHA-256 为 `025DED29ED2B398822BB4FB99EC03FC4C60508200FD539427014B73EAD742FE9`；C0 已另建[固定夹具与清单](../scripts/perf/README.md)，新哈希由测量结果记录。

### 指标与采集方式

当前 `switchTo()` 的 `firstMs` 是等待 150ms 后的采样时间，`fullMs` 是 DOM 静默 600ms 后的时间；滚动层靠最大可滚动 div 猜测。它们保留为历史指标，新测量应给会话与滚动容器稳定标识，并分别记录：

- 从选择会话到会话壳可交互、尾部可见内容完成提交并经过绘制机会的耗时；明确这是绘制代理指标，必要时用 trace 核实。
- 滚动进入屏外代码、公式、图表，到该块可阅读的耗时；按需渲染后不再把 DOM 静默称为全会话完成。
- 主线程最大 longtask、帧间隔和 DOM 数量；固定每次切换或滚动的观测窗口，分别报告长任务总时长与阻塞量 `Σ max(0, duration − 50ms)`，不把自定义窗口的阻塞量当作页面加载 TBT。
- JS 堆、应用主进程与全部 WebView 渲染进程的 PSS，记录 PID、进程代次和时间戳；JS 堆单列，不再加到已包含它的 PSS 中，也不能用 JS 堆代替全部内存。
- 启动可交互、用量冷扫描/缓存命中、ZIP 生成/桥接写入/导入各阶段耗时与峰值内存。

使用独立测试数据和应用数据备份；不要向用户日常数据直接注入，现有 `put` 会覆盖同 ID 记录、`cleanup` 会删除所有 `perf-` 前缀记录。基线与优化版采用相同构建模式、数据、视口和设备，每场景冷加载至少 5 次、热切换至少 10 次，保留全部样本并报告中位数和最大值；至少 20 个样本时再报告 P95。专门连续往返混合/图片/纯文本会话，复现冻结并保存 CPU/GC/渲染 trace。

首轮场景保留 300 条纯文本、300 条混合、50 条重图表、5 张合法大图、1,000 条会话摘要，另加多层分支和总原件体积超过 100 MiB 的备份。大备份体积是本地归档规模，不代表单文件上传额度。覆盖一台较低性能设备与一台日常主力设备；无真机时先形成模拟器结果，真机项保持待验。

## 3 C1 富内容按需渲染

### 实施路线

[CodeBlock](../src/components/markdown/CodeBlock.tsx) 在渲染中同步执行 Prism 高亮，[MathFormula](../src/components/markdown/MathFormula.tsx) 同步执行 KaTeX 排版，[MermaidDiagram](../src/components/markdown/MermaidDiagram.tsx) 挂载后立即排队绘图。按这些路径推断，单加 CSS 不足以消除所有屏外计算。

`content-visibility: auto` 可减少浏览器布局与绘制工作，适合作为独立对照；它不会替应用跳过 React 中已经执行的高亮和公式计算。参见 [MDN content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility)。

1. 先用共享的视口观察机制控制已结束回答中的富内容增强，观察根节点使用实际消息滚动层，预加载带先取约一屏再测量调整。[IntersectionObserver](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) 负责感知区域，重计算仍须由组件显式延后。
2. 屏外保留可读正文/代码原文与必要操作，进入区域、获得 DOM 焦点或被搜索命中时再增强；不能把整条消息变成读屏不可读的空占位。TalkBack 的可访问焦点不保证触发 DOM focus，基础内容必须独立可读。公式可保留 TeX/可读说明或缓存语义结果，不能为屏外备用内容提前运行 KaTeX；图表保留源码或可读说明，验证线性阅读经过屏外边界的行为。
3. 首轮采用进入后保留增强结果，避免反复滚动重算；这主要优化首切，不承诺完整浏览后内存下降。只有内存测量仍失败，才评估卸载与有界缓存。主题、内容、宽度变化必须正确失效。
4. 流式尾部保持即时显示；不要依靠 React 并发调度把单次同步 Prism/KaTeX 调用当作可中断任务。若单个可见块仍长期阻塞，再单独评估分片或 Worker。
5. Mermaid 维持现有串行配置/绘图约束，先减少无关任务并丢弃过时结果；当前[全局队列](../src/services/markdown/mermaid.ts)用于避免主题配置串扰，不直接提高并发。

### 滚动与功能验收

占位/增强的高度变化须接入现有底部跟随、ResizeObserver 和分支切换锚点；用户上滚阅读时不能被拉回底部。验证键盘弹出、横竖屏、断点切换、主题切换、分支切换、重生成、停止、复制、引用、朗读和搜索定位。不能以取消屏外渲染为由缩短请求上下文或改变导出内容。

首轮工程目标如下，属于实施目标，不是已测能力；C0 后按设备分别固定验收值并记录调整理由：

| 指标 | 首轮目标 |
| --- | --- |
| 300 条混合会话热切换至尾部可读 | 中位数 ≤2 秒，最大值 ≤3 秒 |
| 长时间冻结 | 连续往返 20 次不出现 ≥5 秒主线程冻结；同时记录更短阻塞，不能仅靠此项通过 |
| 300 条纯文本切换 | 相同条件下不比新基线中位数退化超过 10% |
| 浏览体验 | 新进入的富内容连续出现，无持续空白；报告帧间隔和最大 longtask，并与基线比较 |
| 内存 | 连续往返 20 次，在同一进程代次的第 0/5/10/20 次操作后各静置 10 秒采样，观察是否持续增长或 OOM；进程重启不算自然回落，设备内存上限由 C0 固定 |

只有优化后仍能证明消息节点挂载/布局是主要瓶颈，才做变高消息虚拟化。侧栏同样先测 1,000 项，不因数量大就默认引入窗口列表。

| [global.css](../src/app/global.css) 与组件样式 | text-size-adjust 被禁用，固定 px 字号/行高/高度较多，动画适配不完整 | 实测后改字体、可滚动区域与命中范围；补减少动态效果并保留静态状态 |

浮层焦点必须支持嵌套和挂在 `body` 下的 Menu/Select Portal，不能简单把“不是当前 DOM 子树”的所有节点设为 inert。保留最上层优先与 busy 关闭守卫；键盘 Escape、Android 返回、读屏关闭应走一致路径。焦点策略依据 [WAI 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

### 设备验收

仅凭 CSS 不能断言 Android 系统字体缩放已经失效。先检查默认/最大系统字体、显示缩放及 200% 文字放大是否生效；若 WebView 不提供有效机制，再补应用文字缩放。正文与设置在放大后保持内容和操作完整，320 CSS px 宽度下正文重排，代码、表格、图表等必要二维内容可局部滚动。采用 [WAI 文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)与[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)作为检查依据，不据此宣称整应用已达到 WCAG 合规。

TalkBack 完成“设置 Key/模型 → 历史切换 → 发送/停止/失败 → 思考/引用 → 图片 → 备份”闭环，覆盖屏外富内容、嵌套确认框、横屏/分屏、IME、明暗主题与减少动画。记录控件名称、角色、顺序、状态、焦点恢复、实际触控命中范围和对比度。桌面键盘与自动扫描是辅助；Android 官方也要求结合[辅助服务手动测试](https://developer.android.com/guide/topics/ui/accessibility/testing)。

## 5 C3 历史检索

**C3a 标题检索**：直接过滤已有摘要，支持中文子串、英文大小写不敏感、空结果、清空和关闭后恢复列表。输入不读取全部会话正文；移动端选中结果后关闭抽屉。检索状态纳入返回层级，不能让返回键越过正在操作的搜索界面直接退出。

**C3b 正文检索与定位**：搜索用户正文和助手最终正文，覆盖所有分支，结果携带 `sessionId/messageId/snippet` 并标记其他分支；首轮不检索思考过程、服务端工具原始块或附件解析内容。标题过滤与正文结果在界面明确区分。

先用可取消的分批扫描验证规模，不在启动时读取全部正文、不将所有正文常驻内存；跨批次让出执行权，IndexedDB 事务内不夹入任意异步等待。若仍不能达到交互要求，再增加可重建的本地索引，索引写入/失效覆盖生成完成、编辑、删除、导入替换与重命名，不能把派生索引当成唯一数据源。

现有 [selectVersion](../src/services/chat/branches.ts) 只切当前路径的兄弟节点。任意命中需要独立的“选择命中祖先路径 + 消息锚点”操作，仅等待命中块就绪后定位，并将焦点移到命中消息/标题、播报定位结果；不能只调用已有版本切换后宣称定位成功。输入检索词时保持输入焦点，低频报告搜索状态和结果数。生成中若禁止切换分支，应说明并允许停止后打开。

验收覆盖深层未选分支、重复命中、结果删除、导入替换、快速改词/取消、语言切换、流式更新和搜索后返回。初始目标为 1,000 摘要的标题过滤在防抖结束后 100ms 内完成；正文首批结果及完成耗时随 C0 的总消息/文本规模设定，不能只报“1,000 个会话”而不记录正文大小。

2026-11-24 实施记录：标题直接过滤摘要；正文按 160ms 防抖、单详情读取、8ms 时间片和每 16 个会话主动让出执行权扫描，不增建索引或全量正文缓存。每条消息只返回一个结果，最多展示 200 条并保留总命中数。输入、取消、关闭、导入及存储失败都有独立状态；生成结束后重新扫描，生成中的目标要求先停止。任意命中先验证完整祖先链，再更新选择、持久化并聚焦消息；只强制增强目标消息，最多等待 10 秒，超时定位可读基础内容并明确播报仍在加载。已定位请求不在断点切换时重放。

## 6 C4 补齐附件上下文与费用保护

以下承接阶段 B，优先于可选工具。2026-11-22 已重新核对[官方文件解析](https://api-docs.deepseek.com/zh-cn/guides/document_parsing/)：每请求最多引用 20 个文档，文字合计不超过 8 MiB，重复引用按多次计；解析成功计费，客户端断开后服务端仍可能完成。核对文档不等于真实 API 验收。

1. **最终请求守卫**：按最终上下文组装规则检查历史和本轮所有 document 引用，覆盖发送、编辑、重生成、续写及补传重试，重复引用不能去重逃过数量限制；尽可能在新增付费上传前拦截已知超限。测试 20/21 边界与跨分支上下文。现有 `FileAttachment.size` 是原件大小，不能冒充解析文字的 8 MiB；没有可信长度元信息时保留准确服务端错误处理。
2. **缺失上下文提示**：研究基线的 [prepareFiles](../src/services/chat/store.ts) 在历史补传失败后仍会继续，[toFileBlocks](../src/services/chat/reply.ts) 丢弃没有 serverId 的附件。C4 已改为先暂停并汇总缺失项，允许重试或明确选择本次省略，避免用户误以为模型仍读到了原件。
3. **上传与再次解析费用**：在选择文档后、首次上传前说明计费时点，提供文字/图文解析选择并保存实际 purpose；备份、恢复、补传沿用选择，旧数据保持原有语义。失效文档再次解析前提供明确操作与授权，复用已成功 ID，停止后不得自动重发聊天。取消不承诺已开始的服务端解析免费。
4. **远端文件边界**：先说明本地删除不等于远端删除；清理策略列出已知引用和影响。远端文件为账号共享，其他 Key/客户端可能使用，本地无引用不足以证明安全删除。现有代码只有删除 API 封装；完整账号文件管理 UI 可另做，阶段 C 不做静默远端清理。依据：[官方 Files API](https://api-docs.deepseek.com/zh-cn/guides/files_api/)。

数量边界、补传失败与取消可先用协议/存储模拟验证；真实解析方式、文件失效与收费提示的 App 链路另记设备和请求结果。不要为制造 429 或账单差异做付费压力测试。

## 7 规模验证与架构决策

| 主题 | 必测 | 何时扩大实现 |
| --- | --- | --- |
| 用量 | 1,000 会话冷扫描、缓存命中、保存后重算、扫描中导入/删除；包含全部分支 | 扫描确为瓶颈后再做与成功保存一致的会话级汇总 |
| 完整备份 | 超过 100 MiB 原件、共享附件去重、低存储、失败重试、恢复后原件/分支/设置/草稿一致 | 证实 ZIP/桥接峰值不满足目标设备后再评估原生文件写入扩展 |
| 数据库 | 摘要读取、详情加载、事务保存、覆盖升级、暂存导入失败恢复 | 有可复现的容量/延迟/可靠性问题且轻量优化不足后再评估 SQLite |
| 消息/侧栏列表 | 富内容优化后重新测挂载、布局、滚动与内存 | 节点数量仍是主要成本时再虚拟化，并重新验收锚点、检索、读屏和选择复制 |

Android 当前按 4 MiB 分块 base64 写缓存，只降低桥接阶段开销。[zipWriter](../src/services/chat/history/zipWriter.ts) 仍保留输出分块组成最终 Blob，不能据“分块写”声称端到端恒定内存。必须分别测 ZIP、桥接、落盘和导入阶段。

OCR 等候“拍照提取并保存文字”的明确工作流；独立 Search/Fetch 等候聊天之外的阅读/检索需求；WebSocket TTS 等候连续朗读的延迟收益与成本证据。当前不以接齐 API 数量作为阶段 C 验收条件。
