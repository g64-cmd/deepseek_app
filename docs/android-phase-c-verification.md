# Android 阶段 C 验证记录

日期：2026-11-22 ~ 2026-11-23（Asia/Shanghai）。C1 批次（富内容按需渲染）代码基线：`develop` / `57fab81` + 探针 v3 测量改动（见第 2 节，随本记录提交）。环境与[C0 基线记录](android-phase-c0-baseline.md)第 1 节相同（Pixel_8 AVD / API 34 / WebView 113、独立 `com.g64_cmd.whalechat.c0` 包、production Web 资源 + debug 原生壳、离线固定夹具 1,006 会话 / 115.4 MiB 原件）。

**结论**：C1 首轮目标全部达到——300 条混合会话热切换尾部可读中位 **1.69 秒**（目标 ≤2 秒）、最大 1.98 秒（目标 ≤3 秒）；对照 C0 基线同一场景热切换中位 40.1 秒，约 **24 倍**改善，且同探针对照（基线 APK + v3 探针）复测为 36.2 秒，排除口径差异。20 轮往返无 ≥5 秒主线程冻结（最大单任务 1.45 秒）；300 条纯文本无退化；20 轮内存四点采样无持续增长。模拟器可验证项通过；真机、TalkBack、大字体与组合场景验收仍待（第 7 节）。

## 2. 探针 v3（测量口径变更）

C1 下屏外门控块有意保持 `data-rich-ready="false"` 且没有任何执行中任务，v2 探针的样本间等待（`settle`）会永等。变更：

- 应用侧新增 `data-rich-gated="true"` 标识（CodeBlock/MathBlock 门控未增强时输出，增强后移除）；
- [browser.mjs](../scripts/perf/browser.mjs) `settle` 只等待已开始增强的块（`:not([data-rich-gated="true"])`），`MEASUREMENT_VERSION` 升为 **3**；`visibleState` 的末轮就绪口径不变（门控中的末轮块仍计为未就绪）。

## 4. 图片场景口径说明（非应用回归）

C0 基线矩阵的图片数字（冷 0.165 / 热 0.133 秒）由**旧版探针（v1 语义，按视口交集过滤）**测得：其就绪检查在图片元素尚未挂载时既不计入等待也不计入缺失（基线样本终态 `images=0, missingImages=0`），即从未等待 2 MiB PNG 的解码。已提交的 v2 探针（`fc68699`，早于任何 C1 改动）已把末轮附件纳入等待。证据：

1. **同探针对照**：基线 APK + v3 探针，图片冷/热 = **0.930 / 1.036 秒**；C1 = 0.716 / 0.978（单样本）与 0.751（热中位）。两构建同口径无差异。
2. **单次切换 A/B**（同一模拟器、同一夹具、逐帧探测）：C1 构建 click→图片 `complete` ≈ 515ms，基线 APK ≈ 570ms；其中 blob 解码（naturalWidth 就绪→complete）分别约 325ms / 392ms，为主导成本且与 C1 无关。

结论：图片场景绝对值（<1.1 秒，含 5×2 MiB 图解码）在两构建一致；C0 基线记录中的 0.13~0.17 秒属旧探针未等待附件的口径，不应作为对比基准。

## 7. 证据范围与剩余项

- 探针 v3 的 75 切换样本与滚动来自单次运行；同探针对照与图片 A/B 为单样本控制，只用于口径甄别，不作分位数。
- **未做**：独立 trace 复测（C1 收益已由矩阵长任务数据体现，若需定位剩余 1.4 秒的组成可补）；CSS `content-visibility` 独立对照（方案 §3 列为可选对照）；卸载/有界缓存（首轮明确不做，仅当内存仍不达标再评估）。
- **组合场景验收挂后续批次共同完成**（方案 §3 验收清单）：分支切换锚点与增强高度变化的组合、键盘弹出、横竖屏、断点切换、主题切换、重生成/停止/复制/引用/朗读/搜索定位；其中大部分为 C2 可访问性验收项。
- 真机（较低性能与主力设备）、现代 WebView、TalkBack、系统字体缩放沿阶段 C 总清单，不因本轮通过关闭。
- Web 端行为变化：与 Android 共享同一渲染链路，滚动进入未增强区域时会短暂先见源码形态（代码原文/TeX/图表源码）随后增强——按方案"屏外保留可读正文"的预期行为，非回归。
