# Android 阶段 C 验证记录

日期：2026-11-22 ~ 2026-11-23（Asia/Shanghai）。C1 批次（富内容按需渲染）代码基线：`develop` / `57fab81` + 探针 v3/v4 测量改动（见第 2 节，随本记录提交）。环境与[C0 基线记录](android-phase-c0-baseline.md)第 1 节相同（Pixel_8 AVD / API 34 / WebView 113、独立 `com.g64_cmd.whalechat.c0` 包、production Web 资源 + debug 原生壳、离线固定夹具；v3 时 1,006 会话 / 115.4 MiB 原件，v4 起新增长尾场景共 1,007 会话）。

**结论**：C1 首轮目标全部达到——300 条混合会话热切换尾部可读中位 **1.69 秒**（v4 复测 1.73 秒；目标 ≤2 秒）、最大 1.98 秒（v4 复测 1.82 秒；目标 ≤3 秒）；对照 C0 基线同一场景热切换中位 40.1 秒，约 **24 倍**改善，且同探针对照（基线 APK + v3 探针）复测为 36.2 秒，排除口径差异。**20 轮内存循环逐轮记录的完整操作观察（v4）中最大单任务 1.73 秒，无 ≥5 秒主线程冻结**；300 条纯文本无退化；20 轮内存四点采样无单调增长。模拟器可验证项通过；真机、TalkBack、大字体与组合场景验收仍待（第 7 节）。

## 2. 探针 v3 → v4（测量口径变更）

C1 下屏外门控块有意保持 `data-rich-ready="false"` 且没有任何执行中任务，v2 探针会永等。变更：

- **v3**：应用侧新增 `data-rich-gated="true"` 标识（CodeBlock/MathBlock 门控未增强时输出，增强后移除）；[browser.mjs](../scripts/perf/browser.mjs) `settle` 只等待已开始增强的块（`:not([data-rich-gated="true"])`），`MEASUREMENT_VERSION` 升为 **3**。
- **v4**（复审 R01/R02 修正）：①`visibleState` 末轮就绪只等待**视口内可见**的富内容块——同一回答开头的屏外门控块保留源码形态不算未就绪，可见但未增强的块仍计入等待（就绪范围 `tail-round-visible`，样本含 `richOffscreen` 计数）；附件（含未挂载缺失统计）与字体检查不变。②驱动的每次切换把长任务观察延伸到该轮已启动增强任务结束（`settleInside`，样本含 `settleUntilMs`/`observedUntilMs`），窗口之后仍在执行的主线程阻塞不再漏记；尾部可读时间定义不变。③内存循环逐轮保存切换与长任务结果（`memoryRounds`）。④夹具新增长尾场景（见第 3 节）。

## 4. 图片场景口径说明（非应用回归）

C0 基线矩阵的图片数字（冷 0.165 / 热 0.133 秒）由**旧版探针（v1 语义，按视口交集过滤）**测得：其就绪检查在图片元素尚未挂载时既不计入等待也不计入缺失（基线样本终态 `images=0, missingImages=0`），即从未等待 2 MiB PNG 的解码。已提交的 v2 探针（`fc68699`，早于任何 C1 改动）已把末轮附件纳入等待。证据：

1. **同探针对照**：基线 APK + v3 探针，图片冷/热 = **0.930 / 1.036 秒**；C1 = 0.716 / 0.978（单样本）与 0.751（热中位）。两构建同口径无差异。
2. **单次切换 A/B**（同一模拟器、同一夹具、逐帧探测）：C1 构建 click→图片 `complete` ≈ 515ms，基线 APK ≈ 570ms；其中 blob 解码（naturalWidth 就绪→complete）分别约 325ms / 392ms，为主导成本且与 C1 无关。

结论：图片场景绝对值（<1.1 秒，含 5×2 MiB 图解码）在两构建一致；C0 基线记录中的 0.13~0.17 秒属旧探针未等待附件的口径，不应作为对比基准。

## 6. 内存与 20 轮往返冻结证据（v4）

20 轮内存循环自 v4 起**逐轮保存切换与长任务结果**（观察覆盖每轮完整操作），"20 轮无 ≥5 秒冻结"以此为据，不再借用矩阵样本：

| 会话 | 轮次 | 尾部可读中位/最大 | 单轮最大长任务中位/最大 | 累计阻塞量 |
| --- | --- | --- | --- | --- |
| 混合 | 20 | 1.82 / 2.16 秒 | 1.30 / **1.73 秒** | 32,476 ms |
| 大图 | 20 | 0.70 / 0.88 秒 | 0.08 / 0.09 秒 | 584 ms |

每轮混合往返中末轮前图表的重渲染贡献约 1.3 秒单任务，20 轮全部远低于 5 秒。四点静置采样（第 0/5/10/20 轮，[v3 摘要](perf/c1-2026-11-23-memory.json) 与 [v4 摘要](perf/c1-2026-11-23-r2.json) 两次运行）：

| 轮次 | 应用 PSS（v3 / v4） | 渲染进程 PSS（v3 / v4） |
| --- | --- | --- |
| 0 | 88.6 / 90.0 MiB | 283.9 / 249.9 MiB |
| 5 | 88.8 / 93.5 MiB | 236.3 / 253.1 MiB |
| 10 | 88.7 / 93.0 MiB | 322.6 / 355.9 MiB |
| 20 | 89.2 / 93.3 MiB | 218.0 / 335.0 MiB |

两次运行均同一进程代次、无连接中断；应用 PSS 稳定（v4 +3.3 MiB/20 轮），渲染进程两次运行四点各有波动且轮内无单调增长（v3 第 20 轮低于第 0 轮，v4 第 20 轮低于第 10 轮）。对照 C0 基线同协议（渲染进程曾至约 808 MiB），高水位明显更低——屏外内容未增强未驻留。四点采样仍不能证明长期有界，沿 C0 口径保留该限制。

## 7. 证据范围与剩余项

- v4 复测 90 切换 + 12 滚动样本与 20 轮逐轮数据来自单次运行；v3 矩阵、同探针对照与图片 A/B 为独立运行/单样本控制，只用于口径甄别，不作分位数。
- **未做**：独立 trace 复测（C1 收益已由覆盖整轮操作的长任务数据体现，若需定位剩余 1.3~1.7 秒的组成可补）；CSS `content-visibility` 独立对照（方案 §3 列为可选对照）；卸载/有界缓存（首轮明确不做，仅当内存仍不达标再评估）。
- **组合场景验收挂后续批次共同完成**（方案 §3 验收清单）：分支切换锚点与增强高度变化的组合、键盘弹出、横竖屏、断点切换、主题切换、重生成/停止/复制/引用/朗读/搜索定位；其中大部分为 C2 可访问性验收项。
- 真机（较低性能与主力设备）、现代 WebView、TalkBack、系统字体缩放沿阶段 C 总清单，不因本轮通过关闭。
- Web 端行为变化：与 Android 共享同一渲染链路，滚动进入未增强区域时会短暂先见源码形态（代码原文/TeX/图表源码）随后增强——按方案"屏外保留可读正文"的预期行为，非回归。
