# Android 阶段 C 验证记录

日期：2026-11-22 ~ 2026-11-24（Asia/Shanghai）。C1 批次（富内容按需渲染）代码基线：`develop` / `57fab81` + 探针 v3/v4 测量改动（见第 2 节，随本记录提交）。环境与[C0 基线记录](android-phase-c0-baseline.md)第 1 节相同（Pixel_8 AVD / API 34 / WebView 113、独立 `com.g64_cmd.whalechat.c0` 包、production Web 资源 + debug 原生壳、离线固定夹具；v3 时 1,006 会话 / 115.4 MiB 原件，v4 起新增长尾场景共 1,007 会话）。

**结论（复核修订）**：C1 混合会话热切换与冻结控制达到首轮目标——300 条混合会话热切换尾部可读中位 **1.69 秒**（v4 复测 1.73 秒；目标 ≤2 秒）、最大 1.98 秒（v4 复测 1.82 秒；目标 ≤3 秒）；对照 C0 基线同一场景热切换中位 40.1 秒，约 **24 倍**改善，且同探针对照（基线 APK + v3 探针）复测为 36.2 秒。**20 轮内存循环逐轮记录的完整操作观察（v4）中最大单任务 1.73 秒，无 ≥5 秒主线程冻结**；20 轮内存四点采样无单调增长。纯文本热切换满足目标，但 v4 的纯文本冷切换中位 1020.7ms，比 C0 的 875.4ms 高 16.6%，不满足原定 10% 目标，因此撤回当时“首轮目标全部达到 / 纯文本无退化”的表述。当前构建的冷切换交替复测见第 11 节；真机、TalkBack、大字体与组合场景验收仍待（第 7 节）。

## 2. 探针 v3 → v4（测量口径变更）

C1 下屏外门控块有意保持 `data-rich-ready="false"` 且没有任何执行中任务，v2 探针会永等。变更：

- **v3**：应用侧新增 `data-rich-gated="true"` 标识（CodeBlock/MathBlock 门控未增强时输出，增强后移除）；[browser.mjs](../scripts/perf/browser.mjs) `settle` 只等待已开始增强的块（`:not([data-rich-gated="true"])`），`MEASUREMENT_VERSION` 升为 **3**。
- **v4**（复审 R01/R02 修正）：①`visibleState` 末轮就绪只等待**视口内可见**的富内容块——同一回答开头的屏外门控块保留源码形态不算未就绪，可见但未增强的块仍计入等待（就绪范围 `tail-round-visible`，样本含 `richOffscreen` 计数）；附件（含未挂载缺失统计）与字体检查不变。②驱动的每次切换把长任务观察延伸到该轮已启动增强任务结束（`settleInside`，样本含 `settleUntilMs`/`observedUntilMs`），窗口之后仍在执行的主线程阻塞不再漏记；尾部可读时间定义不变。③内存循环逐轮保存切换与长任务结果（`memoryRounds`）。④夹具新增长尾场景（见第 3 节）。

## 4. 图片场景口径说明（非应用回归）

C0 基线矩阵的图片数字（冷 0.165 / 热 0.133 秒）由**旧版探针（v1 语义，按视口交集过滤）**测得：其就绪检查在图片元素尚未挂载时既不计入等待也不计入缺失（基线样本终态 `images=0, missingImages=0`），即从未等待 2 MiB PNG 的解码。已提交的 v2 探针（`fc68699`，早于任何 C1 改动）已把末轮附件纳入等待。证据：

1. **同探针对照**：基线 APK + v3 探针，图片冷/热 = **0.930 / 1.036 秒**；C1 = 0.716 / 0.978（单样本）与 0.751（热中位）。两构建同口径无差异。
2. **单次切换 A/B**（同一模拟器、同一夹具、逐帧探测）：C1 构建 click→图片 `complete` ≈ 515ms，基线 APK ≈ 570ms；其中 blob 解码（naturalWidth 就绪→complete）分别约 325ms / 392ms，为主导成本且与 C1 无关。

结论：图片场景绝对值（<1.1 秒，含 5×2 MiB 图解码）在两构建一致；C0 基线记录中的 0.13~0.17 秒属旧探针未等待附件的口径，不应作为对比基准。

## 7. 证据范围与剩余项

- Web 端行为变化：与 Android 共享同一渲染链路，滚动进入未增强区域时会短暂先见源码形态（代码原文/TeX/图表源码）随后增强——按方案"屏外保留可读正文"的预期行为，非回归。

### 远端文件清理边界

单会话删除和全部删除的中英文确认均说明只清理本地数据，不删除远端文件。数据库现有删除事务按所有会话的附件引用保留共享本地原件；本轮未增加远端删除调用。

远端清理应先列明当前本地会话**全部分支**中已知的附件 ID/serverId 引用，再检查同账号其他 Key、客户端和外部调用的引用；当前本地没有引用、导入后没有 serverId，都不能证明远端文件可安全删除。确需远端删除时，应明确说明历史问答可能失效、本地原件仍可保留、将来补传可能再次收费，再由用户指定目标执行。完整账号文件管理 UI 保持后续可选项，本轮只提供边界文案和官方文件管理说明链接，不做静默远端清理。
